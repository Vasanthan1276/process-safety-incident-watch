# Incident Watch: proposed reliability and review improvements

Prepared 13 November 2026, Singapore time. This is a local proposal on `review/incident-watch-reliability-20261113`, based on repository commit `c456d9d8eb7aa5530af1f6ae00bf580ecbe8919c`. No remote branch, pull request, merge, workflow dispatch, account change or deployment has been made.

## What the existing system did

| Stage | Baseline behavior | Material limitation |
| --- | --- | --- |
| Discover | Five query groups through GDELT and Google News RSS; 90-day search window; selected pages fetched in parallel | Search and enrichment caps; sparse publisher access |
| Filter | Substring keyword matches and small score thresholds | `duct` matched `semiconductor`; financial exposure and technology leaks passed |
| Group | Canonical URLs or similar titles plus shared hazards | No event-date/site guard; recurrence and follow-up events could be mixed |
| Date | RSS publication or GDELT seen date stored as `reported_at` | All 517 incident dates were blank; source time was not event time |
| Review | Publisher reliability ≥3 yielded “Confirmed” | This was not independent verification; 57 historical records carried that label |
| Summarize | Description or first extracted sentences, up to a fixed length | Google News boilerplate repeatedly became the incident summary |
| Present | Search, stream/review/status filters, score badges, three sections, archive | Long queue; no company/location fields; no source-health or freshness warning |
| Operate | Weekly collection, data commit, GitHub Pages deploy, permanent database and snapshots | A total discovery failure left old diagnostics; same-day snapshots could overwrite |

## Proposed behavior

- Require an event signal and industrial context; exclude routine investment/business headlines, nonphysical technology leaks, figurative fire, software/font/game uses of foundry, and disused-building stories without an industrial release signal.
- Keep real incidents even when financial effects are discussed. Retain suspected events, conflicting reports and incomplete leads for human review. Genuine metal-foundry events are cross-industry, not automatically semiconductor.
- Preserve all historical records in the raw database and all 55 historical JSON files. Screened-out history remains searchable in a separate scope. Audit rejected new discoveries with reasons and links.
- Automatically combine only reports sharing a canonical URL unless known incident dates conflict. Keep cross-publisher matches as reversible suggestions with links; preserve source revisions and all existing incident IDs.
- Separate dates; label GDELT discovery time correctly. Leave unknown incident dates unknown. A reviewed date requires a source URL.
- Replace operational auto-confirmation with Needs review. Preserve legacy labels and explain them. Require explicit reviewer, timestamp, notes and source-linked claims for human annotations.
- Attribute titles and usable descriptions to their sources, separate preliminary/disputed signals and reported consequences, and leave confirmed facts empty until human review supplies them. Company/location mentions are labelled unverified and never inferred from the publisher's country.
- Present potential fab lessons as review questions, without asserting causes, failed safeguards, recommended engineering modifications or formal Tier classifications.
- Show each provider's success/failure counts, recorded errors, last known success, article retrieval outcomes and coverage limits. Keep healthy-provider results and historical fallback data during failures; never refresh collection age merely by rebuilding the page.
- Add a searchable, paginated review workspace, duplicate navigation, scope/date/status filters, local draft decisions and JSON export. Retain the previous layout at `classic.html` with corrected status wording.
- Add offline CI and restrict collection/deployment to `main`. No paid services, credentials, analytics or external scripts were added.

## Preview and remaining limits

Open `docs/incident-watch-preview.html` in a modern browser for the portable, embedded-data preview. It uses the actual stored records and the new review projection, with no live data request. The served version is available by running the README's local HTTP server command. Original-source links still navigate to external news pages when clicked.

The existing live page was visually inspected. A rendered visual check of the changed page could not be completed: the connected desktop and cloud browsers could not access the isolated local server, and browser policy rejected a self-contained data URL. No alternate browser-control workaround was used. The dashboard behavior tests execute the production script against a minimal DOM harness; they do not validate real-browser layout, downloads, keyboard navigation or responsive rendering. Desktop/mobile visual checks and a normal HTTP-origin draft save/reload/export remain approval-stage checks, not claimed passes.

The entity dictionary and screening rules remain incomplete and English-focused. Potential duplicate links require review; the system intentionally does not infer a shared event from company and hazard alone. Generic or late follow-ups can remain separate. Legacy bad merges are retained, not silently rewritten. No incident dates, causes, consequences or independently confirmed facts have been invented.

Before publication, review the preview and a representative sample of retained, ambiguous and screened-out records. Push a review branch / draft PR only with approval, run remote CI, and obtain separate approval for merge and deployment.
